# Проверка контроля СИЗ

## Реализация

Каски и жилеты проверяются внутри рамок людей.

- YOLO26n обнаруживает людей и транспорт.
- ByteTrack присваивает Track ID.
- Область каждого достаточно крупного человека передаётся PPE-модели.
- Каски и жилеты сопоставляются с областями головы и туловища.
- Возможное отсутствие СИЗ подтверждается по правилу «5 из 7» среди кадров с новыми результатами.
- для каждого `Track ID` и типа события действует пауза 10 секунд перед повтором.

Веса берутся из `models/best.pt`. В текущей [конфигурации](../configs/configuration.yaml)
порог равен `0.40`, размер входа — `640`, минимальная высота рамки человека — 120 пикселей.
При интервале `3` модель СИЗ запускается на каждом третьем кадре, если в нём есть подходящие люди.

Порог 0.40 выбран для касок на этапе 5.
Для жилетов он используется как начальная настройка.

## Первоначальная проверка на видео

На проверенном ролике присутствовали два человека.

| Сценарий | Результат |
|---|---|
| Человек без каски и жилета | Сформированы ppe_helmet_missing и ppe_vest_missing |
| Человек в каске без жилета | Сформировано ppe_vest_missing |
| Сохранение нарушения | Повторы событий происходят с интервалом не менее 10 секунд |

В представленном журнале ложного события отсутствия каски
у человека в каске не зафиксировано.

После перехода к вырезанным областям людей на проверенных роликах визуально стало больше найденных касок и жилетов.
Количественное сравнение по видео тогда не проводилось.

## Производительность и ограничения

В первоначальной проверке скорость колебалась примерно от 7,6 до 14 FPS.
Актуальные замеры полного запуска приведены в [отчёте о скорости](benchmark/README.md).

Количество вызовов PPE-модели зависит от числа анализируемых людей.

Возможны пропуски СИЗ и ложные обнаружения.
Временное подтверждение уменьшает влияние кратких пропусков,
но не устраняет устойчивые ошибки модели.

При перекрытии людей одна рамка каски или жилета может попасть в области двух человек.
При обрезанной голове проверка пропускается. Если нижняя граница области туловища за краем кадра, статус жилета остаётся неизвестным.
Порог высоты 120 пикселей выбран как начальная настройка.

При смене Track ID один человек может получить новое событие.
Cooldown измеряется по времени выполнения программы.

Подтверждённые события пишутся в журнал и сохраняются в `events/` вместе с JSON и снимком.
