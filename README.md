# Industrial Vision

Учебный проект по разработке программного модуля технического зрения
для промышленного мобильного роботизированного комплекса.

## Назначение

Модуль предназначен для анализа видеопотока, обнаружения людей
и транспорта, проверки контролируемых зон, контроля средств
индивидуальной защиты и выявления визуальных признаков дыма,
огня и разлива.

Результаты анализа преобразуются в события с сохранением JSON
и подтверждающего кадра. REST API предоставляет состояние системы,
сохранённые события и изменение настроек во время работы.

## Запуск

Команды выполняются из корня проекта:

```bash
source .venv/bin/activate
python -m src.main
```

Программа загружает конфигурацию и модель, открывает источник
видео и отображает результаты детекции.

На изображении выводятся:

- рамки объектов, названия классов и confidence;
- FPS общего цикла обработки;
- время вызова детектора в миллисекундах;
- количество детекций текущего кадра.

Выход: q или Esc при активном окне, Ctrl+C в терминале.
После завершения видеофайла программа останавливается.

Журнал сохраняется в logs/application.log.

## Конфигурация

Основные настройки находятся в configs/configuration.yaml:

- camera — источник видео и параметры подключения;
- models — пути к моделям и пороги confidence;
- zones — полигоны контролируемых областей;
- events — временное подтверждение и cooldown событий;
- storage — каталог событий; автоматическая очистка по retention_days пока не реализована;
- ppe — модель и параметры контроля СИЗ;
- fire_smoke — модель и параметры дыма/огня;
- spill — экспериментальное выделение изменений поверхности.

Источник видео задаётся в camera.source.
Baseline-веса людей и транспорта: models/yolo26n.pt.

Конфигурация актуального PPE-датасета: configs/dataset.yaml.

Блоки zones, events и storage используются в рабочем конвейере.

## Baseline-детектор

Используется предобученная на COCO модель YOLO26n
из библиотеки Ultralytics.

Веса: models/yolo26n.pt.

Документация модели:
https://docs.ultralytics.com/models/yolo26/

Модель выполняется на CPU.
Параметры задаются в блоке models файла
configs/configuration.yaml.

При конфигурации classes: [0, 1, 2, 3, 5, 7]
обрабатываются классы person, bicycle, car,
motorcycle, bus и truck.

Детектор возвращает список Detection:
class_id, class_name, confidence, x1, y1, x2, y2.
Координаты рамок выражены в пикселях исходного кадра.

Для получения весов из корня проекта:

    mkdir -p models
    python -c "from ultralytics import YOLO; YOLO('models/yolo26n.pt')"

Веса и видеоданные не включены в Git.

## Специализированная PPE-модель

На основе предобученной YOLO26n выполнено дообучение
для обнаружения касок и сигнальных жилетов.

Актуальный эксперимент: ppe_exp02.

| Часть | Источник | Изображения |
|---|---|---:|
| train | Construction-PPE | 1132 |
| val | CHV | 243 |
| test | CHV | 243 |

Целевые классы: 0 — helmet, 1 — vest.

Параметры обучения: максимум 30 эпох, imgsz=640,
batch=8, seed=42, patience=10.

Обучение штатно завершилось ранней остановкой после 18 эпох.
Лучшие веса выбраны по результатам 8-й эпохи.

Финальная проверка best.pt на validation:

| Метрика | Значение |
|---|---:|
| Precision | 0.7932 |
| Recall | 0.6567 |
| mAP50 | 0.7078 |
| mAP50–95 | 0.3401 |

Детектор СИЗ интегрирован в видеоконвейер.
Для helmet при confidence=0.40 на test получены
Precision=0.8512, Recall=0.7182, F1=0.7791.
Условия оценки описаны в [docs/helmet_thresholds.md](docs/helmet_thresholds.md).

## События, сохранение и журналирование

Реализовано формирование событий обнаружения людей,
нахождения людей и транспорта в контролируемой зоне,
возможного отсутствия каски или жилета, обнаружения дыма
и огня, потери и восстановления видеопотока.

Для аналитических событий используются временное
подтверждение и ограничение частоты повторов — cooldown.

События сохраняются в структуре:

events/YYYY/MM/DD/<event_id>/event.json
events/YYYY/MM/DD/<event_id>/snapshot.jpg

Подтверждающий кадр сохраняется до нанесения визуализации.
При недоступности источника событие потери потока сохраняется
без кадра.

Журналы разделены на application.log, ai_events.log,
camera_errors.log и system_monitoring.log.
Предусмотрена ротация файлов журналов.

Дополнительно реализован экспериментальный алгоритм
выделения изменений поверхности относительно первого кадра.
Он проверен на видеозаписях и подключён к механизму событий
spill_detected.

На сценах с людьми и транспортом выявлены ложные срабатывания.
Поэтому режим разлива выключен по умолчанию:
spill.enabled: false. Для экспериментов требуется неподвижная
камера и исходный кадр без пятна. Надёжное распознавание
жидкости в общем видеопотоке пока не подтверждено.

## REST API

API запускается вместе с `python -m src.main`.
Документация: http://127.0.0.1:8000/docs.
API доступен, пока работает приложение.

- GET /health — доступность API;
- GET /status — камера, модели, FPS и применённые настройки;
- GET /cameras — состояние камеры;
- GET /events — последние сохранённые события;
- GET /events/{event_id} — событие по UUID;
- POST /config/thresholds — изменение порогов detector, ppe, fire_smoke;
- POST /config/zones — изменение полигона текущей зоны.

POST возвращает HTTP 202: команда принята и применяется между кадрами.
Применённые значения доступны в /status. YAML при этом не изменяется.
Неверные значения отклоняются с HTTP 422.
