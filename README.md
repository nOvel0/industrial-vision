# Industrial Vision

Учебный проект для промышленного робота. Программа читает видео с камеры или из файла, находит людей и транспорт, следит за запретной зоной, проверяет каски и жилеты и ищет дым, огонь и разливы.

На видео видны рамки объектов, зоны, маска разлива и FPS. Подтверждённые события сохраняются в JSON вместе со снимком. Их можно посмотреть через локальный REST API.

## Установка

Проект проверялся на Ubuntu с Python 3.12 и процессором AMD Ryzen 5 5600H. Модели в текущей конфигурации работают на CPU.

Команды выполняются из корня проекта.

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install --index-url https://download.pytorch.org/whl/cpu "torch==2.14.1" "torchvision==0.29.1"
python -m pip install -r requirements.txt
python -m pip check
mkdir -p data datasets models
```

Каталоги `data/`, `datasets/` и `models/` исключены из Git. Перед запуском положите видео в `data/`, а веса — в `models/`.

| Файл | Назначение и источник |
|---|---|
| `yolo26n.pt` | Готовая модель Ultralytics для людей и транспорта. Команда загрузки приведена ниже. |
| `best.pt` | Каски и жилеты. Используется `weights/best.pt` из архива `ppe_exp02_export.zip`. Обучение описано в [блокноте PPE](scripts/train_ppe.ipynb) и [карточке данных](docs/dataset_card.md). |
| `fire_smoke.pt` | Дым и огонь. Сохраните `best.pt` из [репозитория модели](https://huggingface.co/rabahdev/fire-smoke-yolov8n/blob/main/best.pt) под именем `fire_smoke.pt`. |
| `spill_yolo26n-seg_new.pt` | Маски разливов. Возьмите `spill_yolo26n-seg.pt` из `spill_mixed_yolo26n_results.zip` и переименуйте. Обучение описано в [блокноте разлива](scripts/train_spill_mixed_colab.ipynb). |

Общую модель можно загрузить из корня проекта.

```bash
python -c "from ultralytics import YOLO; YOLO('models/yolo26n.pt')"
```

Файл `best.onnx` используется отдельно для [сравнения скорости](docs/benchmark/README.md). Для обычного запуска достаточно четырёх файлов из таблицы.

## Запуск

В [конфигурации](configs/configuration.yaml) укажите `camera.source`. Сейчас выбран `data/test1.mp4`. Для другого ролика замените путь. Для локальной камеры можно указать индекс, например `0`.

```bash
source .venv/bin/activate
python -m src.main
```

Программа открывает окно OpenCV. Для выхода нажмите `q` или `Esc` в окне либо `Ctrl+C` в терминале. При завершении видео программа останавливается и сохраняет замер скорости в `runs/benchmark/pipeline.json`.

## Настройки анализа

| Блок конфига | Что задаёт |
|---|---|
| `camera` | Источник видео и паузу перед повторным подключением. |
| `models` | Модель людей и транспорта, классы, порог, размер входа, устройство и интервал запуска моделей. |
| `zones` | Запретную зону для людей и транспорта. |
| `events` | Подтверждение событий для людей и транспорта и паузу перед повтором. |
| `ppe` | Модель СИЗ, порог и минимальную высоту рамки человека. |
| `fire_smoke` | Модель, порог, область поиска и подтверждение дыма и огня. |
| `spill` | Модель, порог, область пола и подтверждение разлива. Значение `enabled: false` отключает этот анализ. |
| `storage` | Каталог событий. Очистка сохранённых файлов выполняется вручную. |

При `models.inference_interval: 3` модели и трекер обновляют результат на кадрах 1, 4, 7 и дальше. Видео отображается целиком. Между обновлениями на экране остаются последние рамки и маска. Для запуска моделей на каждом кадре задайте `1`.

Для событий людей, зон, дыма, огня и разлива используется правило «3 из 5», для отсутствия СИЗ — «5 из 7». В эти окна входят только кадры, на которых запускались модели. При увеличении интервала нужно больше кадров исходного видео для подтверждения.

В `fire_smoke.polygon` и `spill.polygon` задаются отдельные области поиска. Модель получает вырезанную часть кадра, а пиксели за границей полигона закрываются. Координаты `[x, y]` задаются от 0 до 1, значение `[0.5, 0.5]` соответствует центру кадра. Для поиска по всему кадру укажите `polygon: null`.

## События и API

Файлы события сохраняются в `events/YYYY/MM/DD/<event_id>/`.

- `event.json` содержит тип события, время, идентификатор камеры и доступные данные обнаружения.
- `snapshot.jpg` содержит кадр до нанесения рамок и масок. Для потери видеопотока запись может содержать только JSON.

Журналы находятся в `logs/`. Основной журнал — `application.log`, события — `ai_events.log`, ошибки камеры — `camera_errors.log`, скорость и нагрузка — `system_monitoring.log`.

Пока приложение работает, можно открыть [страницу API](http://127.0.0.1:8000/docs) в браузере.

| Запрос | Что делает |
|---|---|
| `GET /health` | Проверяет, отвечает ли API. |
| `GET /status` | Возвращает состояние источника видео, FPS и текущие настройки. |
| `GET /cameras` | Возвращает состояние камеры. |
| `GET /events` | Показывает последние сохранённые события. |
| `GET /events/{event_id}` | Показывает одно событие по его идентификатору. |
| `POST /config/thresholds` | Задаёт пороги для общего детектора, СИЗ, дыма и огня. |
| `POST /config/zones` | Задаёт полигон запретной зоны для людей и транспорта. |

Ответ `202` означает, что команда принята. Программа применяет её между кадрами и показывает новые значения в `/status`. Изменения действуют до перезапуска.
